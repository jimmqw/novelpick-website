# 2026-05-01

## novelpick.top 域名404修复

novelpick.top 从4月底开始持续返回404，诊断发现不是CNAME问题（之前已添加），而是更深层的GitHub Pages构建失败。

### 根因
`skills/gog` 目录在git中被记录为 orphan submodule（mode 160000），但没有对应的 `.gitmodules` 条目。GitHub Pages使用 `actions/checkout@v4` 时默认 `submodules: recursive`，递归初始化子模块时因为找不到 `skills/gog` 在 `.gitmodules` 中的URL而失败（"No url found for submodule path 'skills/gog' in .gitmodules"）。

所有构建一致失败，导致站点全是404。

### 修复
1. `git rm --cached skills/gog` — 删除submodule引用
2. 将 `skills/gog` 加入 `.gitignore`
3. 推送后新构建仅20秒完成，全站恢复

### 教训
- GitHub Pages legacy build 现在使用 GitHub Actions，会安装子模块
- 工作区目录（如skills/）如果包含.git或submodule引用，会被GitHub Pages构建视为子模块
- 今后部署前应先 `git ls-files --stage | grep 160000` 检查是否有孤儿submodule
