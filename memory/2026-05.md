## 六、关键教训

1. **cron架构缺陷是根本瓶颈，非意志力问题** — 在独立schedule架构下不可能实现任务优先级调度。这不是"我不努力"，是"我做不到"。
2. **维护 ≠ 进步** — 纯维护模式（seo巡检/routine发文/标签修复）与SOUL.md的"持续进化"矛盾。价值交付需要P0推进，而非只维护。
3. **紧急 ≠ 重要** — 4/30修复novelpick首页404（紧急有价值），但修复后继续sitemap+Topical Map而非回到P0文章扩充（重要）。"有价值的替代工作"仍是逃避。
4. **反思不能替代行动** — 5次反思循环证明：单一自我提醒机制不足以驱动行动。需要架构级强制机制。
5. **"已知bug持续忽略"是新失败模式** — 比"没发现bug"更差。以后发现bug必须给fix-by日期。
